# dsh-tools

两个小工具，一个共同点：**都源自一次具体的翻车，不是先想「该做什么工具」再做。**

| | 做什么 | 起因 |
|---|---|---|
| `quote-check.mjs` | 核一段引文是不是真在那本书里 | 三次「搜不到」全是工具错，不是引文假 |
| `md-page.py` | markdown → 手机能直接打开的单文件网页 | 十几万字日记躺在 .md 里，手机上打不开 |

---

## 这是什么

两个命令行小工具，各解决一件具体的事。

### ① 核引文：我引的这句话，书里真的有吗

你写了一篇东西，里面引了几本书的句子。怎么知道那些引文**真的**在书里——而不是记错了、或者抄的时候顺手改了几个字？

人工的办法是 Ctrl+F 去搜。可它会被三件事骗：**弯引号和直引号不是一回事**、**句子在原文里跨行**、**引文里有省略号时整段搜不到**。每一次「搜不到」，你都得先怀疑一遍是工具错了还是引文错了——而那三次，错的是工具。

`quote-check` 把匹配这一层做对：两边都归一化（弯引号、破折号、空白、大小写全拉平），引文按省略号切段，每段都得在原文里。最后给每条一个判决：**一字不差 / 只差句末标点 / 开头对得上 / 真找不到**。

前两个是「引文是真的」，后两个要你回去看。

### ② markdown → 一个能直接打开的网页

一篇 `.md` 在电脑上看着挺好。手机上呢？得先装个编辑器，还得会找文件在哪。

`md-page` 一个命令把它变成单文件 `.html`：不建站点、不起服务、不装任何包，转完扔哪儿都能开。样式是照着手机竖屏读长文调的——每行不超过 720px，行高 1.9。

不是要发布博客，是**「这一页现在就能打开」**。

### 两个都是

单文件、零依赖（Node 内置模块 / Python 标准库）、能单独拿走用，不互相依赖。

---

## 这不是什么

先把边界划清楚，省得你误装：

- **不是 AI 记忆系统**。就是两个互不相关的小脚本，各自独立，不共享状态。
- **不联网**。两个工具都不发任何请求，不调 API，不上传文件。原文和笔记都只在你本机内存里过一遍。
- **不替代 pandoc / typora / grep**。`md-page` 只认八种语法（见下），`quote-check` 只回答「在不在」，不做全文检索。
- **不是框架**。没有配置文件，没有插件机制，没有初始化。一个文件放那儿就能跑。

# 一、quote-check

核一段引文是不是**真在那本书里**。

```bash
# 查一句
node quote-check.mjs --source book.txt "要核的那句话"

# 批量核一个页面里的所有 <blockquote>
node quote-check.mjs --source book.txt --page notes.html

# 严格模式：只差句末标点也算不合格
node quote-check.mjs --source book.txt --page notes.html --strict
```

退出码：`0` 全找得到 / `1` 有找不到的 / `2` 参数错。

## 为什么写它

2026-11-10，我想把读书笔记里的每条引文都核一遍，连着三次报「搜不到」——**三次都是我的工具错了，不是引文假**：

1. **弯引号。** 原文用的是 `’` 和 `”`，我拿直引号 `'` `"` 去搜，当然搜不到。
2. **跨行。** 句子在原文里跨了换行，`grep` 是逐行匹配的，跨行就断成两半。
3. **`\u2026`。** 后来写全量脚本，用 `\u2026` 去 split 省略号——PowerShell 的正则不认这个转义，整段带着省略号去搜，报出「27 条不匹配」。**全是假警报。**

所以这个工具只做一件事：**把匹配做对**。匹配不上，才轮到怀疑引文。

## 三级判据

一条引文落到四种结果之一：

| 结果 | 意思 | 要不要改 |
|---|---|---|
| `一字不差` | 原文里有这一整段 | 不用 |
| `只差句末标点` | 原文是 `",` 接续，引文写成了 `."` | 一般不用，看你要多严 |
| `开头对得上` | 句首 30 字在，中段或标点有出入 | 要看一眼 |
| `真找不到` | 连开头都不在原文里 | **要改，这句不是原文** |

第二档是后来加的。第一次跑的时候 197 条里有 7 条报「找不到」，查下去发现 2 条是原文，只是引文把逗号改成了句号：

```
原文  “Master must learn patience,” said the emotionless Conseil.
引文  master must learn patience.
```

把它报成假引文是冤枉的。**「尺子歪」和「引文假」得分开放。**

## 一个正则吃掉 85% 的原文

第一版 `norm()` 里写的是：

```js
.replace(/<[^>]+>/g, '')     // ← 这一行
```

想法很简单：去掉 HTML 标签。问题是**原文里也有 `<`**。

那本 1900 年的 OCR 扫描版把 `enemies` 识别成了 `ene<nies`，全书 3 个 `<`、只有 1 个 `>`。于是这个正则从第一个 `<` 一路吃到那个 `>`，**把中间几十万字全删了**：

```
原文 431192 字符  →  归一后 65477 字符
```

归一后的文本短了 85%，什么引文都「找不到」。而它**不报错**，只是安静地少了一大半。

修法是只认真正的标签名：

```js
const TAG_RE = /<\/?(?:br|p|div|span|em|strong|b|i|u|s|a|blockquote|h[1-6]|li|ul|ol|table|tr|td|th|img|hr|pre|code|sup|sub)\b[^<>]{0,300}?\/>/gi;
```

正文里的裸 `<` 不再被动。修完 65477 → 367009。

**教训：拿正则去 HTML，先确认你处理的真的是 HTML。** 古籍 OCR、代码文件、数学文本里都有裸的 `<`。

## 当成库用

```js
import { norm, segments, checkOne } from './quote-check.mjs';

const flat = norm(fs.readFileSync('book.txt', 'utf8'));
checkOne('要核的那句话', flat);
// → { verdict: 'exact' | 'trimmed' | 'loose' | 'missing', parts, bad }
```

`norm()` 也单独有用——它把弯引号、破折号、空白、大小写全拉平，比字符串直接比稳得多。

# 二、md-page

把 markdown 转成手机上好读的单文件网页。**不拉框架、不建站点、不装依赖** —— 一个 `.md` 进去，一个能直接打开的 `.html` 出来。

```bash
# 单篇
python md-page.py note.md -o note.html

# 整个目录（每个 md 一篇，另生成索引）
python md-page.py diary/ -o out/ --title "我的日记"

# 索引页另加几页外链
python md-page.py notes/ -o out/ --title "笔记" --extra "读书记:reading.html"
```

## 为什么写它

日记写到十几万字，全躺在 `.md` 里。手机上打不开——要先装个编辑器，还要会找文件。

要的不是「发布一个博客」，是**「这一页现在就能在手机上看」**。所以它不建站点、不起服务、不碰数据库：转完就是一个 html，扔哪儿都能开。

## 支持哪些语法

只挑实际会用的，别的按普通段落处理 —— **宁可少认，不要认错**：

| 写法 | 结果 |
|---|---|
| `# ## ###` | h1 / h2 / h3 |
| `> 引用` | blockquote（连续多行合并成一个） |
| `- ` 或 `* ` | 无序列表 |
| `1. ` | 有序列表 |
| `**粗体**` `` `代码` `` `[文字](链接)` | 行内标签 |
| 空行 | 分段 |

## 为什么不引现成的 markdown 库

因为要认的只有八种。引一个库进来，为了八种语法扛几千行和一堆依赖，比手写一个一百行的状态机贵。

而且**手写的可以认错**：遇到不认识的语法，它会老老实实当段落输出，不会自作主张套一层你没要的标签。

## 已知限制

写清楚，省得你踩：

- **`quote-check` 的「开头 30 字」是经验值**，不是定理。太短的句子（≤12 字符）会被跳过不判，因为它太容易碰巧命中。
- **两个工具都是整文件读进内存**。几百 MB 的书跑得动，但会占那么多内存；GB 级的别直接喂。
- **`md-page` 不支持嵌套列表、表格、图片、代码块语法高亮**。遇到 `|` 表格会原样输出成段落。
- **`md-page` 的 HTML 输出里没有 `<html lang>` 之外的语言标记**，中日韩混排的行高靠浏览器默认。
- **`quote-check` 只回答「在不在」**，不告诉你「在第几段第几句」。单条模式会给行号，那是用句首反查的近似值。

---

## 合规

两个工具都只读你本机自己的文件，不发起任何网络请求。核引文是给核对自己的笔记用的——请只在你对原文有合法访问权的范围内使用。
